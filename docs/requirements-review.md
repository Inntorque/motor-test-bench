# 需求基线与本轮检查

更新：2026-10-09。本文件作为当前需求与验收状态的入口；设备细节见[试验台方案](test-bench.md)，传感器依据见[设备与通信笔记](device-and-protocol.md)，CAN 范围见[接口约定](can-interface-contract.md)。

本轮状态：需求与问题已复核，界面和记录改进已完成；S01–S13 通过本轮模拟验证，实际命令与覆盖范围见[验证记录](#6-本轮验证记录)。网页仍为模拟原型，未实现真实通信、未访问硬件、未发布 GitHub Pages。软件测试通过不代表实机验收通过。

## 1. 已确认的需求

| 项目       | 需求基线                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------- |
| 产品目标   | 非专业操作人员能完成连接、设定、观察、记录和导出，常用操作清楚直观                              |
| 交付形式   | 网页；仓库为 Inntorque/motor-test-bench，GitHub Pages 是部署目标                                |
| 机械链     | 电机 → 减速箱 → 动态扭矩传感器 → 磁粉制动器；制动器只提供负载                                   |
| 设备规格   | 扭矩传感器各有 50 N·m、100 N·m；制动器也有两种规格，具体配对与并发方式待确认                    |
| 两路供电   | 电机电源给驱动侧供电；制动电源给线圈供电，通过电流调节加载                                      |
| 三路 RS485 | 传感器、制动电源、电机电源分别占一条独立 RS485 通道，不共用 A/B 总线                            |
| CAN        | 自家驱动板使用 CAN；适配器为 LC_CANABLE_V2.1，可修改固件；USB CDC/SLCAN + Web Serial 为接入方向 |
| 测量位置   | 传感器直接测得减速箱输出扭矩与输出转速；跨轴推算需另外确认减速比、效率和方向                    |
| 电流语义   | 制动目标电流、实际制动电流、电机供电电流与电机相电流分别命名；电流设定不能代替扭矩实测          |
| 界面风格   | 保持读数、曲线和控制清晰；按用户意见不再使用 Shaders 或装饰动效                                 |

独立 RS485 通道可以由独立适配器或多路网关的独立端口提供，不能由“三路”推定网关数量。50/100 N·m 代表设备规格，不能直接视为整套台架允许的试验上限。现有传感器手册要求 DC 24 V 辅助供电，来源尚待确认；这一待定项不增加第三个可控电源角色。

## 2. 操作流程与边界

目标流程：**选择已登记配置 → 分别连接设备 → 检查读数与状态 → 编辑并应用设定 → 开启所需输出 → 记录试验 → 分别停止输出和记录 → 回看与导出**。

首屏保持四个设备角色、三张主读数卡、实时曲线、两组控制和记录入口。电机电源当前只显示待接入和“— V / — A”，控制范围确认前保持占位。设置抽屉承载连接细节、接入计划与演示限制。

“应用设定”“开启输出”“停止输出”“停止记录”是不同操作。记录停止后仍能继续观察输出；停止全部模拟输出后仍能记录减速与卸载过程。全局停止按钮只关闭当前模拟电机与制动输出，不能作为硬件急停，也不证明真实轴系已停转。

本轮保留单个已选量程的模拟工作台。不会因两个规格而新增双台并行控制，也不会在电机电源功能未确认前新增电压设定、限流或输出开关。

## 4. 本轮审查发现与处置

| 问题                                 | 原因或影响                               | 本轮处置                                               |
| ------------------------------------ | ---------------------------------------- | ------------------------------------------------------ |
| 负扭矩曲线贴零线                     | 所有指标共用非负坐标                     | 为扭矩使用带正负范围的坐标                             |
| CSV 与回看时间原点不同               | CSV 使用模型运行累计时间，历史图自行归零 | 统一记录相对时间，并兼容旧记录                         |
| 操作事件刷新后消失                   | 事件仅存于页面，没有归属试验             | 保存配置快照和记录事件，补充历史展示与事件导出         |
| 本地异常与多标签页可能影响记录完整性 | 校验较浅，保存时覆盖整份页面内列表       | 严格校验、保护损坏原值，并在 Web Locks 下合并最新记录  |
| 跨页面时难以判断仍在输出或记录       | 状态与停止入口分散在工作台               | 添加全局摘要与停止全部模拟输出入口                     |
| 草稿与实际设定容易混淆               | 编辑状态与启动按钮缺少联系               | 提示未应用值，限制启动且保留停止能力                   |
| 演示入口覆盖用户的断线操作           | 演示初始化直接恢复三个连接标记           | 演示保留断线状态，并持续提醒                           |
| 历史仅回看单一指标                   | 难以把输出响应与加载变化对应起来         | 增加三指标切换与缺失点统计，短于 10 秒的窗口显示小数秒 |

本轮还调整辅助文字对比度和手机按钮。EVG-D200 关键协议页已复核，现有笔记已正确保留停止位冲突、缩放待验证与主动上传无法通信切回等限制；无需按模拟交互推断真实协议。

## 6. 本轮验证记录

测试日期：2026-10-09。浏览器测试使用 `/opt/google/chrome/chrome` 与 Playwright 创建的独立临时上下文，没有使用操作人员的浏览器会话，也没有访问硬件。

| 命令                                                                                              | 实际结果          | 覆盖范围                                                                                                         |
| ------------------------------------------------------------------------------------------------- | ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| `npm test`                                                                                        | 20/20 通过        | 模拟模型、输入边界与精度、CSV 相对时间、旧记录兼容、记录与事件校验、损坏存储保护、读写失败、加锁合并及无锁提示等 |
| `CHROME_PATH=/opt/google/chrome/chrome npm run test:ui`                                           | 通过              | 记录、CSV、断线缺口、暂停视图继续记录、配置切换、输入精度、记录恢复及 1440 / 1024 / 768 / 390 像素宽度布局       |
| `npm run build`                                                                                   | 通过              | `dist/` 仅包含 HTML、CSS、JavaScript 网页产物，不含手册或试验记录                                                |
| `CHROME_PATH=/opt/google/chrome/chrome TEST_URL=http://127.0.0.1:5174/ npm run test:requirements` | 8 组通过，11.1 秒 | 对生产构建的本地 preview 执行下列需求流程                                                                        |

生产 preview 的需求流程覆盖：

1. 未应用输入阻止启动，已有输出仍可停止。
2. 演示不擅自重连已断开的通道，断线提示与缺失值持续存在。
3. 跨视图查看全局状态，停止全部模拟输出后记录继续。
4. 新记录保存配置和事件，数据及事件 CSV 可导出，历史三指标与缺失点统计可用。
5. 旧记录相对时间兼容，负扭矩显示在零轴下方。
6. 损坏原始存储不被覆盖，当前有效记录仍可导出。
7. 支持 Web Locks 的双标签页并发保存保留双方记录；另一页清除存储后提示当前记录未保存，并保留内存中的试验。无 Web Locks 的降级提示由逻辑测试覆盖，不承诺无锁并发不会冲突。
8. Playwright 推进约 5 分钟模拟时钟后，记录在 1500 点结束并保存，末点为 299.8 秒，模拟输出仍保持开启。

第 8 项验证的是记录点数上限与状态行为，使用了模拟时钟；未进行真实设备采集或长时性能测试。生产 preview 仅在本机 5174 端口提供构建结果，GitHub Pages 仍未发布。待协议项目 P01–P05、实机项目 H01–H07 及第 5 节的剩余交付均保持未完成。
