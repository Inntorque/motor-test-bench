# 空载与带载自动测试

入口：左侧 **专项测试 → 空载 / 带载自动测试**。填写本次装配适用的参数并点击“启动顺序测试”后才发送电机运行命令。连接、刷新、查看历史均不启动运动。原电流步进、被动测量和原有试验记录保留。

## 当前使用：指定 Iq 恒流带载与全参数记录（2026-10-19）

工作台顶端 **恒流带载测试 / 全参数记录** 可直接进入。默认选中“带载测试 → 指定 Iq 恒流运行 · 全参数记录”，空载与原 Iq 递增脚本仍可切换。

1. 在工作台接好电机驱动、扭矩传感器、电机电源、制动电源。按实物选择 SSJ 或 RU；设置两台电源的目标电压、电流及适用限幅，再开启电源输出。电机驱动此时保持 IDLE/输出关闭。脚本要求双电源均有新鲜读回且输出 ON、传感器在线，以及有效编码器、电流、速度、NTC 和设备限值。
2. 填写**指定目标 Iq**（必须自行输入，0.001 A 分辨率，不超过设备当前限值）、**开始记录前运行等待**（默认 2 s，0～10 s）和**全参数记录时长**（默认 30 s，1～240 s），确认测功台和负载设置后启动。沿用 MODE 5 电流环，Id 固定 0 A，不调整 PID。指定的是 Iq 目标，真实 Iq 单独保存；电流环不保证恒定转速，也不保证达到目标电流。
3. 电机从零设定启动，收到运行状态后写入指定 Iq，等待配置时间，再自动开始记录。此模式不递增电流，不执行空载定位或最高转速搜索，不自动调整制动负载。
4. 记录后台直接落盘，不使用网页的 1500 点记录缓存。扭矩有效帧逐帧保存（包括原始扭矩/转速整数、帧号、PC 接收时间、换算值、计算功率）；电机保存工作台每次新读回快照，包括指定 Iq、固件报告的斜坡参考 Iq、实际 Iq/Id、多圈位置、转速、NTC、编码器有效性、输出、模式与保护状态。双电源独立后台只读轮询，保存实际 V/A/W、目标 V/A、全部原始状态/设置寄存器、量程、限幅、协议和其他已返回字段。命令、成功应答、失败原因和启动配置也保存。
5. 到时自动停机，确认输出 OFF 后继续采集约 1 s；报告统计仅包括记录窗口中的有效读数，尾段保留在原始记录中。双电源输出保持操作者原设置。保护、接口掉线/过期、设定被其他控制端改变、传感器缓存溢出/序号中断、记录文件写入失败、页面心跳超时等异常均停止电机，保留部分记录与原因；不自动重启。

### 文件与时间含义

位于 `recordings/automatic/<id>/`，结果页提供下载：

- `timeline.csv`：**全参数时间序列**，按来源分行。`source` 为 `motor`、`motorSupply`、`brake`、`sensor`、`sensor_frame` 或命令/生命周期事件；其他接口列留空，不插值、不把慢速数据伪装成每个扭矩帧的同步测量。`payload_json` 保存该事件的完整字段，包括当前没有单独 CSV 列的字段。
- `timeline.jsonl`：相同事件的完整结构化数据，每行一个 JSON 对象，完整配置、快照、寄存器与命令应答可按 `payload` 解析。
- `report.json`：配置、起止时刻、各来源事件数、记录完整性异常、实际 Iq/转矩/转速/功率/NTC 统计、停止原因与停机确认。
- `data.csv`：兼容原有电机轮询记录，包含准备和运行阶段；不替代全参数时间序列。

`elapsed_s` 按记录器单调时钟连续递增；`recording_elapsed_s` 在正式记录开始前为空，随后从零计时。`pc_recorded_unix_s` 是该事件写入记录器的 PC 时间，`source_received_unix_s` 是来源快照/帧原有接收时间，**绘制测量曲线时使用 `source_recording_elapsed_s`（来源原有接收时间减正式记录起点）作为横轴**。批量到达的传感器帧仍使用各自原始时间戳；不能用文件行的写入时刻代替测量时刻。准备阶段保存配置及命令，正式窗口保存所有观察到的新快照/有效帧，`post_stop` 为停止尾段。所有“全部参数”均指当前工作台实际接入并读回的字段，不代表未接入的固件参数或每个底层 CAN 帧。电机按现有约 10 Hz 状态读取，扭矩按实际接收帧速率，电源按各自 RTU 事务速度更新；重复缓存不作为新读数。各设备没有硬件同步触发，不能据此声称同步带宽。

API 沿用 POST `/api/automatic/start`，参数增加 `group:"loaded"`、`loadedMode:"hold"`、`targetIqA`、`settleS`、`durationS`、`loadConfirmed:true`；下载路径增加 `timeline.csv` 与 `timeline.jsonl`。未指定 `loadedMode` 的旧 API 请求仍按原带载递增模式处理，避免改变既有脚本含义。

## 空载脚本

1. 核对电机真实新鲜反馈、电角校准、NTC、当前电流保护限值、减速比和速度限值；台架已确认允许来回控制及连续旋转，不设置软件机械角度限位。制动必须反馈 OFF，或在无法读取状态时由操作者明确确认励磁已关闭。已知 ON 不能被人工确认绕过。
2. 可选定位往返：使用现有位置环 MODE 3，默认以启动时当前位置为原点，按位移 −10°、0°、+10° 正序、逆序执行，重复 2 次；也可手工切换绝对坐标或修改目标点。每点保持末 0.4 s 使用独立新位置反馈记录实际均值、末次位置误差、平均误差、误差 RMS、最大绝对误差及位置标准差/峰峰值。误差为“实测−目标”，不填写允许误差，不因误差大小中止；不足两个新位置样本属于数据不足，会中断。不会自动调整 PID。
3. 确认停机后，可选最高转速自动搜索：使用速度环 MODE 2，从零设定开始，默认按输出端 1 rpm 步长逐级提高。每级末半段记录实测均值、偏差、偏差 RMS、标准差和峰峰值；所有完整级的数据都保留，不以允许误差或稳态容差筛选，也不因偏差/波动数值中止。瞬时峰值与末段均值分开记录。
4. 根据采样精度与实测散布自动观察转速平台：比较带宽取格式精度保守底值和 3 倍均值标准误估计的较大值。采样全为整数转子 rpm 时底值取 1/减速比，否则取 0.01/减速比；带宽需小于半个升速步长，且实测正向转动可分辨、实测均值显著低于目标时，追加一次相同目标的保持。两次均值在合并比较带宽内才记“观察到平台”；不满足则继续采样升速，直到时间预算或保护/控制器边界。此规则用于启发式平台观察，不是产品合格标准，不代表严格统计置信度或额定极限。
5. 保护触发、软件停止阈值、搜索超时或控制器可用范围用尽时结束，并分别记录原因；这些情况不标记为已测得电机自身极限。确认输出关闭，保存电机反馈 CSV 和 JSON 报告。

位置直接沿用参考工程已调好的编码器及减速比，上电相对多圈坐标不重新清零，不强制归一到 0～360°。网页默认“相对启动位置的位移”，实际绝对目标在启动时换算并存入报告；接口未提供 `positionReference` 时仍按原有绝对坐标处理，避免旧脚本被误解。定位按目标点往返，可跨越多圈；升速和带载运行不因累计角度或越过原上下限而停止。参考接口的位置命令已经转换减速比，工作台不会再次相乘；反馈位置除以减速比。位置命令仍须能被接口表示（输出坐标 ±200000° 且转子毫度值为有符号 32 位），这属于协议编码范围；当前坐标超出位置命令范围时阻止定位启动。速度命令和反馈均为转子 rpm，工作台转换为输出端 rpm。

这些结果表示现有编码器反馈的跟随与重复离散性。用同一编码器闭环和读回不能独立验收输出轴绝对定位精度。当前参考接口速度目标范围为 **±300 转子 rpm**，同时受设备参数 ID11 限制，搜索时自动读取 `min(300, ID11) / 减速比` 作为控制器可用边界，不提高固件限值。到此边界只报告“控制器限幅，尚未测出电机自身上限”。报告记录最高实测末段均值及其目标、平台观测目标、瞬时峰值和每级波动；不输出通过/不通过。平台只代表本次供电、负载、控制参数、步长和保持时间下的响应。

## 带载最大转矩脚本

适用已接好“制动负载—轴承—扭矩传感器—轴承—被控电机”的台架。本次制动器为 50 N·m；专用额定电压、电流、持续耗散和最高转速尚无资料，因此制动电源由操作者预先设定并开启，脚本不自动调制动电压/电流。

1. 要求制动电源真实在线、实际输出 ON、扭矩传感器持续在线，并明确确认已设置本次负载。
2. 启动独立逐帧扭矩采集，再使用 MODE 5 从 0 A 设定开始，按填写的 Iq 步长和保持时间递增。
3. 不预设首级最小转矩门槛，测得零值也保留；电源 ON 只证明励磁供电状态，机械负载连接由现场确认。制动设定改变、扭矩达到 50 N·m 边界、传感器丢帧或失联等情况结束脚本。
4. 设备实际保护时立即停止递增，记录保护结果。达到本次电流上限则正常结束，不把设定上限标为保护。
5. 发送停机并确认新反馈输出 OFF；继续被动记录约 1 s，分别报告停机前最大转矩幅值和停机后窗口最大转矩幅值。不会自动解除保护或重试启动。

最大转矩是**本次预设负载和电流范围下测得的值**，不能据此认定机械额定极限、连续额定转矩或硬件安全转矩关断。原始扭矩、转速、计算轴功率按传感器有效帧保存；电机 Iq、Id、位置、速度和 NTC 按后台反馈保存，两个来源的时间戳是 PC 接收时间，并非硬件同步。

## 参数、停止及记录

- 测试步骤已有可编辑默认值：相对位移 −10°、0°、+10°，定位往返 2 次，每级保持 2 s，输出转速步长 1 rpm，升速搜索 120 s，带载 Iq 步长 0.1 A。无需预填位置误差、速度容差、角度上下限、待测最高转速或最小负载转矩。
- 电流及 NTC 停机保护默认在启动时读取设备：电流使用现有桥接/设备可用限值，温度使用设备 NTC `limit_c`。读不到自动保护值会在任何运动命令前拒绝启动，不能用猜测值填充；可在折叠的“停机保护设置”填写更低停止值，不可超过设备限值。此设置独立于测量结果，不是产品合格门槛，配置来源随报告保存。
- 每级保持 1–30 s，定位/带载阶段累计保持不超过 240 s，另限 10 s 命令开销；速度搜索总预算 1–240 s，包含升速、保持及重复采样。固件运行计时作为备用停止边界。默认配置只定义测试过程，不代表已经完成实机运动验收或控制参数整定。
- 位置/速度环沿用现有固件限幅，工作台电流阈值为后台采样监测，不能代替硬件瞬态限流；不写入控制参数、校准、存储或固件。
- 页面电机状态轮询保留原 2 s 心跳约束。关闭页面、控制源断线、编码器/电流/温度反馈无效、NTC/设备保护、超出本次边界、模式改变或意外停机均终止脚本。异常结束保留部分数据与原因。
- “停止脚本并停机”、原工作台的“停止电机输出”都可取消剩余步骤。自动任务期间拒绝其他启动及电源/传感器配置改变；电源 OFF 操作先停止电机。停止未收到新设备确认时报告“未确认”，不宣称已停机。
- NTC 记录初温、末温、最高温及相对初温变化；原被动温度测量仍支持较长时长记录和可选环境温度。
- 自动记录：`recordings/automatic/<id>/data.csv`、`report.json`。带载逐帧数据在报告 `rawTorqueRecordId` 指向的 `recordings/specialized/<id>`，页面提供直接下载。该辅助记录随脚本收尾，不作为独立稳态合格测试。
- 服务重启不恢复运动，未完成脚本标记中断。Ubuntu/Windows 关闭脚本先结束自动任务并核对停机，再执行原有电源输出检查。

## 目前覆盖与后续项目

已覆盖空载位置误差与重复离散性、转速自动搜索及响应平台观测、带载电流递增与本次最大转矩、实际保护记录和 NTC 温度变化；已有稳态转矩/转速波动、特性曲线和功率计算继续使用。旧字段 `speedMaxRpm`、`positionToleranceDeg`、`speedToleranceRpm`、`minLoadTorqueNm` 不作为新脚本的终点或验收门槛。使用步长、保持时间、次数及搜索时间定义测试步骤。

尚不自动给出额定速度/转矩、持续额定能力、转动惯量、反向启动转矩、启停允许转矩、转矩控制精度及转矩常数、精确阶跃响应与频带宽度、转矩/功率密度等结论。分别还需要明确测试工况、控制/负载能力、时间同步或质量参数。机械刚度、背隙、伺服静刚度、振动/噪声按要求暂缓。

API：GET `/api/automatic/status`；带本机令牌 POST `/api/automatic/start` 与 `/api/automatic/stop`；GET `/api/automatic/files/<id>/data.csv|report.json`。
