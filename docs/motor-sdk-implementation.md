# MBP/1 与驱动板 SDK 实施交付（2026-10-26）

本次是供当前板 OTA 和人工全程测试的代码交付。目标线协议 1.0、SDK 1.0.0、主机 API 1、记录 schema 2；第二块实物驱动板、Windows 实物 USB-CAN 与当前板运行时序尚未验收，不标为通用性正式发布通过。

## 交付内容与运行链路

浏览器 → 同源 `/api/v1/` / SSE → 单个 Python 工作台应用（5173）→ 单适配器所有者 → USB-CAN / MBP → 板端 SDK → 原 FOC。电源和传感器仍各自独立 RS485 通道。

工作台与固件 A/B 分区无关。选槽、试启动确认、升级与回退由固件工程、Bootloader 和独立 CAN-OTA 工具负责，不进入 MBP、SDK 核心或工作台配置。驱动板运行任一槽位时都提供同一 MBP 接口；工作台根据协议版本、能力和真实状态决定可运行功能，厂商固件版本仅供追溯。

- `protocol/schema.json`：唯一对象编号、类型、模式和复合布局；生成器输出 C/Python 常量、对象表及 DBC。固定向量在 `protocol/golden.json`。
- `motor_sdk/`：C11 核心、静态缓冲、独立 STOP 槽、ISO-TP 双通道、会话/代际/序号检查与四条精确去重记录；含当前实际板端口、集成差异和可编译模拟端口。
- `workbench/devices/motor.py`：原生协议、能力与限值、缓存、启动/停止确认；没有品牌固件版本门槛、ID7 或工程路径识别。
- `workbench/test_engine.py`：保留电流步进、固定电流对照、最大输出策略；`coupled_current.py` 保留独立两次点击、力矩保持、联合停转与终点冻结。
- `workbench/control.py`：唯一浏览器控制租约和停止编排。浏览器 750 ms 心跳；原有效租约按场景集中为单独电机/自动脚本 2 s、联动 2.5 s、仅电源/制动及新独立操作 3 s；当前驱动原有 1000 ms 监督及主机 250 ms CAN 会话心跳保留。删除测试引擎之间的代喂和重复页面租约。
- `workbench/events.py`、`acquisition.py`、`recording.py`：共享缓存采集、事件与记录会话。原始 CAN 组、诊断、命令/应答、传感器帧、双电源与现有 CSV/JSONL 投影保留。测试关联手动记录时不会结束它。
- `web/src/apiClient.ts`、`deviceStore.ts`：显式客户端及单 SSE 来源。主电机、制动、联动面板直接订阅；停止确认强制查询最新状态，不能由之前的缓存代替。

删除工作台运行包的整套 `vendor/xige_foc` 工程网页服务、私有 HTTP 电机适配器、全局 fetch 替换，以及 8766→8892 / 网页→8766 两级转发。独立固件工程和维护工具保留在原目录。启动器保留一次旧安装关闭/配置迁移操作，不作为新工作台的电机通信适配器。

## 首次切换

本次没有关闭正在运行的旧服务，没有开启电源、启动电机或进行 OTA。

1. 先结束原试验，再在仓库目录执行 `npm run stop`。启动器会先请求旧服务完成停机确认，再关闭它记录的进程；外部启动的工程网页需按原方式关闭。新启动器发现旧 8766/8892 仍在运行会明确拒绝并行接管 CAN。
2. 由独立固件维护流程部署已接入 SDK 的应用。本轮当前板配套构建标识为 `0x0A3D`；旧 `0x0A3C` 不实现 MBP，不能用于原生 SDK 联测。这是当前板交付状态，不是工作台的版本号准入条件。
3. `npm run start`，打开 `http://127.0.0.1:5173/`。只有一个工作台应用进程；连接不会自动开启输出。
4. 点击一键连接，确认 SDK、固件、节点、就绪与反馈。电机电源仍只用万瑞达，开启前只读核对已有 24 V / 20 A 预设；制动电源及边界保持。
5. 操作者先点①空载启动，再单独点②加载，亲自观察并完成全程测试。

本机配置示例为 `workbench.example.json`，只配置工作台的设备通信，原生节点默认 1。首次启动对旧 `workbench.local.json` 做 schema 2 迁移前保存副本到 `.runtime/config-migration/`，旧私有节点仅保留在备份中，不生成 OTA 配置、不写设备参数。SDK 首版使用经典 CAN 500 kbit/s；工作台当前实现 ZQWL 通道，不能把未实现的适配器显示为已支持。

## 当前板保持和新增的边界

现有 MODE5/7、定位/速度本地实现由板级回调映射；没有重写 FOC。R/L、PI、9 V 电压限幅、PWM、100 A/s 斜坡、10 kHz、过流/NTC/编码器/采样保护均保留；NTC 本上电周期历史跳闸锁定也保留。最大输出仍本地连续分配，主机不反复试探加流。

原生生产控制拒绝旧使能、目标、任意参数写入与校准操作，避免绕过 SDK 会话。旧停止仍撤销 SDK 代际，OTA 和维护只读保留。重新校准需独立维护构建/原工程工具，不在通用 API 增加任意写参数接口。

当前板没有可用的实测母线电压/电流通道，不将供电依据或估算值冒充实测。实际 Iq/Id、参考、目标、动态可用 Iq、dq 电压边界、相电流与 ADC/PWM 代际分开记录。温度带自己的转换源时间，不宣称与 dq 同拍。源反馈超时沿用原 1.5 s 判断；较短的诊断质量告警不增加停机线。

多圈位置直接取原始 64 位累计计数；原始微转整数通过 JSON 十进制字符串保留。台架档案迁至 `profiles/bench.json`，原 9.67 保持；编码器比较页原 9.78 的差异保留来源，待现场核实，没有擅自覆盖。

当前板没有确认的负 Id 许可，能力不声明弱磁，默认 Id=0。新板只有声明并验证能力与范围后才接受相应运行配置。

## 与方案基线补齐的内容

为保留原定位/速度脚本，在预留运行配置空间补齐 `0x1009 velocity_target:i32`（0.001 rpm）、`0x100A position_target:i64`（微转），不改变已有对象语义。`0x6000..0x6006` 用于 READ_STATE 的状态、会话和最近 STOP；结构见 schema。

SAMPLE 的 16..23 补齐相电流、ADC 序号、PWM 代际、温度源时间和原始编码器计数。当前首版采用固定 20 ms 配方并返回实际周期；其他配方明确返回 UNSUPPORTED。SDK API 采用由调用者静态分配的 `mb_sdk` 上下文承载内存。
