# 专项测试 V2

2026-10-27。专项 V2 包含专项页面、专项执行与计算。后续统一了电机测试配置、显示换算与完整记录；扭矩工作台布局、原控制算法、设备驱动、SDK 和协议不变。当前交付经离线测试，实机测量由操作者验证。

## 三个入口

- **性能**：T-N 现有工况采集、最大输出阶梯加载、低速电流分级 Kt、指定工况。最大输出加载复用原 `/coupled-current/start/load/stop`，仍需分别点击空载启动和开始加载。采集不发运动指令；Kt/指定工况用原 `/automatic/start/stop` 控制权和停止确认。
- **定位精度**：按目标点正反向接近、多轮重复，保存每次稳定采样窗口。相对坐标以当前反馈位置为起点，绝对坐标沿用设备多圈坐标。轨迹包含两端的接近距离，启动前须确认机械允许。位置按原 64 位微转对象发送。
- **温升**：只记录现有工况，或专项保持指定 Iq/速度；支持升温和停机后的降温段。时长按配方，不沿用旧专项 240 s/1 h 上限。结束条件为配方时长、用户停止、可选热稳定条件或既有设备/通信边界。

## 指标口径

电机的裸机/带减速箱配置统一在右上角管理，详见 [电机测试配置与减速比](test-setups.md)。专项不再单独填写比例、轴端或质量/体积，启动时冻结所选配置，与工作台折算显示和完整记录共用。裸机比例为 1；带减速箱使用现场填写的实际比例。传感器安装在减速箱后时，T-N、Kt 和密度属于输出端或总成，不按比例直接当作电机本体数据。

- T-N 保留原始过程与独立窗口的转矩/转速/实际 Iq/Id；稳定窗口单列。功率按同一传感器帧 `T*n*2*pi/60` 计算，不拼接不同工况的最大值。
- 原始转矩采样峰值与有效窗口转矩均值峰值分开。帧率不代表动态带宽，带宽确认和传感器说明随报告保存。
- Kt 按实际电流的独立准稳态级拟合，包含截距和 R²；要求有效低速窗口及合适的 Id 均值/波动。按相峰值等效 Iq 定义，不使用电源 DC 电流，不假设减速箱效率。
- 质量和体积未知时密度留空；额定转速/转矩为操作者录入的铭牌值，短时扫描不认证连续额定能力。
- 温度以真实新测点时间去重。无环境温度时只报告温度与相对初温变化。现有 NTC 不自动等同绕组测温。
- 热稳定使用配方窗口、温度斜率及同段电流/速度/转矩稳定性。缺少负载数据不认定连续工况。升温段结果与降温段分开；满足条件时保存该配方下的连续工况候选点和密度，不作通用额定声明。
- 定位先报告驱动反馈均值误差、重复标准差/极差、正反向差，不能据此宣称输出端绝对精度。

## 外部角度参考

结束定位后点击历史中的“查看完整结果”，下载参考 CSV 模板。按访问编号填写 `reference_deg`，由独立测量仪提供角度。填写仪器名称、参考零位并确认坐标对齐后导入。期望参考坐标为“参考零位 + 记录的 nominalDeg”。不要把驱动自己的编码器数据作为独立参考。

分析在专项页面离线进行，不发送设备指令，也不改写原始驱动报告。分析另存于本浏览器，重新查看同一记录时读取；可导出含参考输入/仪器/结果的专项 JSON 和参考 CSV。跨电脑或清理浏览器前必须导出分析报告；浏览器保存失败会提示立即导出。部分导入会标记覆盖不完整，不给出完整绝对精度验收结论。

## 数据保存

主动专项仍用 `recordings/automatic/<id>/`，只记录专项用 `recordings/specialized/<id>/`。新报告有 `specializedSchema=2`，旧报告只读展示，原始文件不迁移不删除。

- `data.csv`：按来源分行，保留原始传感器帧、独立电机快照、温度转换、命令结果、统计窗口和定位访问结果。来源时间为 PC 接收时间；设备温度源时间保留在载荷中，不宣称硬件同拍。
- `timeline.jsonl`：专项采样的完整载荷。不会把 1 kHz 转矩帧伪装成 1 kHz 电机反馈。
- `report.json`：对象、设备身份、配方、初始状态、指标和结束原因。
- `recordingId`：关联现有共享全参数记录器，提供完整参数 CSV/JSONL 和后台事件。已有手动记录只关联，不因专项结束而关闭。

预览有界抽点，温升保留统计总数、首末/最高温和稳定窗口，不把整段运行数据堆在浏览器内存。数据缺口单列，受影响窗口不参与有效窗口指标，原始数据保留；不因此新增固件保护条件。

## 实机前检查

操作者确认轴端、传动比、测点/散热、转矩传感器校准及范围，主动配方确认供电/负载及运动路径。电机和驱动必须已按原方式连接并声明所需能力。专项不烧录、不写入调参、校准或保护参数。
