# 浏览器运行延迟与资源优化

2026-11-03。以 `fc210fa` 为对照，保留四个 APP 的画面、功能、数值口径、协议、设备命令、心跳、停止确认和保护。没有改变采样率、CAN/串口波特率、SWD 时钟或可见图表的刷新上限，没有增加运行依赖。

## 改动边界

- 工作台请求只计算所需结果。心跳、STOP、传感器增量读取、端口与配置读取不再提前准备整套显示路由；令牌、控制代次和停止流程保持原样。
- 一次完整状态发布复用同次电机快照、健康状态和记录状态。电机快照从每次发布 5 次降为 1 次；独立读取仍取当前状态，没有跨请求保留旧快照。
- Worker 到页面仍使用原消息结构和 JSON 数值规范化。页面内部直接读取已收到的数据，只有读取 EventSource 的 `data` 文本时才编码 JSON；原 SSE 文本读取继续可用，未过滤事件、删减字段或减少记录。
- 新传感器帧写入缓存后立即唤醒接收器，不必先等下一次 20 ms 轮询；保留原轮询入口、防重入、缓存容量和 30 Hz 显示上限。无新帧且状态/配置未变时不再反复提交相同画面。接收、记录和显示继续各自保留原职责。
- 历史记录的有效值、峰值和相对时间轴在选择或指标改变时重算，避免实时数据更新时反复扫描已选历史记录。
- SG-6010HB 与 7010 波形批量读取直接判断遥测时效，不再为此生成整张参数显示表。波形不可见或页面隐藏时停止申请动画帧，返回后恢复；可见时仍沿用原动画帧节奏和时间轴。
- Bootloader 日志逐条追加，保留相同时间文本、顺序、滚动和导出；阶段或整数百分比文字未变化时不重写文本节点。每次原进度数值仍写入进度条，总进度、备份、擦写、回读与完成判断不变。
- 总网关沿用原单渲染器、480×480 机械图案、悬停转动及数据箭头效果；SDK、冻结协议、参考工程、Boot 镜像和 MCU 固件未修改。

两个 `source-manifest.json` 的 `uiSha256` 跟随当前页面源码更新，原导入页面哈希另存为 `importedUiSha256`；`files`、`importedFiles` 和参考 Python 代码保持原值，以保留来源追溯。

## 固定数据回放

使用相同数据先预热，再各测 5 次取中位数。下表是对应函数完成整组回放的耗时，不是整页 CPU、硬件传输延迟或实际测试时间的同幅下降。

| 路径与工作量 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 心跳路由，2000 次 | 128.05 ms | 2.85 ms |
| 传感器增量读取，2000 次 | 131.28 ms | 2.42 ms |
| 完整状态构造，2000 次 | 147.24 ms | 62.26 ms |
| 事件入缓存与增量读取，1000 包 / 20000 帧 | 10.04 ms | 2.54 ms |
| SG-6010HB 波形批量读取，2000 批 × 20 点 | 67.40 ms | 2.21 ms |
| 7010 波形批量读取，2000 批 × 20 点 | 66.41 ms | 1.60 ms |

固定状态下，全部序列化显示路由与旧实现完全相同。帧序号、缩放配置、原始数值和保留范围一致；另覆盖缓存返回值隔离、通知取消、旧 SSE 输入、遥测过期和 STOP 不依赖显示计算。

## 浏览器对照

虚拟 USB-CAN 只连接并读取，不启动虚拟电机，也不访问实物设备。同一次 3 秒观察中，页面主线程的 `JSON.stringify` 次数为 **102 → 12**，`JSON.parse` 为 **27 → 12**；任务耗时为 **0.186 → 0.149 s**，脚本耗时为 **0.111 → 0.085 s**。这一组浏览器时间与堆快照受调度和 GC 影响，不据单轮观察承诺固定整机降幅。

120 次浏览器至 Worker 的健康读取往返，中位数均约 **0.3 ms**，P95 均约 **1.2 ms**；本轮不能据此宣称 CAN、串口或 SWD 的物理往返变快。收益主要来自减少重复工作、减少后台绘制，以及新帧不再等待轮询才进入既有显示调度。

两个独立电机页面离开视口/隐藏后，400 ms 测量区间内动画帧申请为 **0**；返回后恢复绘制，固定时钟下的波形像素一致。四个 APP 的可见全文一致，并对比固定时钟、相同动画帧下的截图；字体栅格化仅允许不超过 0.02% 像素、单通道差不超过 5 的微小误差。本轮三个电机 APP 截图逐像素相同，Bootloader 仅有 3 个字体边缘像素相差 5。名义 1000 帧/秒界面回放仍显示约 30 Hz，按钮、标题、编码器路径和响应式布局保持一致；20000 帧的缓存回放核对每批增量和保留范围，没有额外丢帧。

## 验证与复现

Python 检查需使用已安装 `requirements-motor.txt` 的环境。

本地通过 JavaScript **110/110**、Python 全量 **260/260**，以及四个 APP 浏览器回归、配置锁定、最大输出、专项测试、总网关头像、固定画面对照和模拟烧录检查。

```sh
npm test
npm run build
python3 scripts/build_gateway.py
npm run test:browser
npm run test:gateway-icons
node tests/runtime-latency-ui.mjs
node tests/runtime-latency-replay.mjs
python3 -m unittest discover -s tests -p 'test_*.py'
```

`runtime-latency-ui.mjs` 自行构建虚拟串口夹具；不要求此前运行其他浏览器测试。Pages 工作流也执行该检查。设置 `LATENCY_SITE_DIR` 可读取已保存的旧静态站，设置 `LATENCY_COMPARE_VISUALS=1` 对比其截图/可见文本；`runtime-latency-replay.mjs` 通过 `LATENCY_SOURCE_DIR` 对比旧源码，旧源码需先生成原参数元数据。

本次源码与静态站基线、测量 JSON、截图及检查日志位于 `.runtime/latency-20261103/`，基线提交写在 `baseline-commit.txt`。基线、日志、性能夹具输出不进入发布内容。软件回放不替代长时间实机负载验收；本轮没有开启实物电机、电源输出或 Flash 擦写。
