# 网页版上位机交互初稿

日期：2026-10-09。产品设计建议；已实现模拟交互原型，真实硬件功能尚未实现。当前确认项、改进范围与验收状态统一见[需求基线与本轮检查](requirements-review.md)。硬件依据见[设备与通信笔记](device-and-protocol.md)。用户已选择网页版、GitHub 部署方向。文档保留原文件路径以维持已有链接。

## 已实现的布局原型

当前采用浅色仪器台风格，扭矩读数使用深色面板突出，曲线与控制按钮保持独立。按用户意见移除 Shaders，不再添加装饰动效。应用只有两个主视图：

- **试验工作台**：顶部为量程配置与四个设备角色；主区域保持减速箱输出扭矩、输出转速、实际制动电流三张读数卡，下方为曲线与记录；右侧仍为电机控制与制动电流控制。电机电源显示“待接入”，供电读回占位放在设置抽屉。
- **试验记录**：查看当前浏览器内已完成的模拟试验，回看扭矩、输出转速或制动电流，查看缺失点、配置快照和操作事件，导出数据或事件 CSV；旧记录没有的配置和事件明确保留为未知。

设备抽屉展示接入计划，原有 CAN 驱动板、传感器、制动电源可模拟断开 / 连接，三个模拟角色初始已连接，电机与制动输出初始关闭。新增电机电源只显示供电电压“— V”、供电电流“— A”和待协议确认，不开放模拟连接、设定、限流或输出开关。50/100 N·m 是演示配置，切换不写入传感器；运行或记录时锁定配置。原有转速与制动电流输入先编辑、再应用、再单独使能输出，动作保持不变；首屏提供“运行加载演示”入口。

当前有效数据与操作均为模拟，电机电源仅有占位；设置范围、减速比与响应关系不是实际设备规格。CSV 和记录标明模拟来源；已完成记录存入浏览器本地存储，活动记录暂存内存，每场演示最多 1500 点。导出列明确标注减速箱输出和制动电流：`gearboxOutputTorqueNm`、`gearboxOutputSpeedRpm`、`brakeCurrentA`、`motorTargetSpeedRpm`、`brakeTargetCurrentA`。本轮补充相对时间和记录元数据，保留旧模拟记录的读取与导出兼容。页面尚无真实通信、传感器清零/滤波、文件导入、活动记录恢复、长时增量存储或自动恒扭矩控制，GitHub Pages 尚未发布。下文仍描述后续真实接入的产品目标，不代表全部已实现。

### 本轮已完成并验证的模拟改进

- 扭矩图显示正负量程；记录时长、历史横轴与 CSV 统一为本场相对时间，旧记录导出兼容归零。
- 新记录保存演示配置快照与操作事件，历史增加三指标切换、缺失点统计及事件 CSV；不足 10 秒的历史窗口使用小数秒横轴。
- 严格校验本地记录，保护损坏原始数据；支持 Web Locks 时加锁读取最新记录并合并多标签页保存，无锁时提示使用单个页面。其他页面清除存储后，保留当前内存记录并提示尚未保存。
- 增加跨视图可见的输出/记录摘要和“停止全部模拟输出”，该操作不结束记录、不代表硬件急停。
- 草稿未应用或非法时阻止启动，正在输出时始终保留停止能力；演示不恢复用户主动断开的通道，断线持续提醒。
- 改善辅助文字对比度和手机控制按钮。

本轮逻辑测试 20/20、浏览器流程、构建及生产 preview 的 8 组需求流程均通过；环境与覆盖范围见[验证记录](requirements-review.md#6-本轮验证记录)。原型继续保留 1500 点上限，该上限已通过 Playwright 模拟时钟验证；活动记录恢复、长期存储与实机采集仍未完成。电机电源继续为待接入占位。

场景更新：机械链已确定为“电机 → 减速箱 → 动态扭矩传感器 → 磁粉制动器”，磁粉制动器只作负载。电机电源和制动电源是同类型的两台独立电源，分别给电机驱动侧、制动线圈供电；传感器所需 24 V 辅助供电来源待确认，不增加第三个可控电源角色。传感器和制动器均有 50/100 N·m 两种规格，组合与并发需求待定。实测值命名为“减速箱输出扭矩”，不能直接称为电机轴扭矩；电机供电电流也不等于电机相电流。完整设备关系见[试验台设备与接入方案](test-bench.md)。

接入方向更新：LC_CANABLE_V2.1 采用 USB CDC/SLCAN + Web Serial，首轮能力见 [CAN 接口约定 v1](can-interface-contract.md)。首页显示“电机驱动板”“动态扭矩传感器”“制动电源”“电机电源”四个角色。后三者各占一路独立 RS485，不共用总线；CAN 也独立接入。两台电源均已确定采用网口转 RS485，可使用多路网关的独立通道；网关型号、数量与协议待定，不推定两台网关或两个不同 IP。传感器保留 USB-RS485 方案；驱动板和两电源的设备协议仍待确认。

电源接入按通用模块与两个独立设备实例设计，协议确认后复用兼容的适配器。每台电源分别配置网关端点（地址 + 端口/通道）、RS485 串口参数、设备地址和额定上限，独立维护设定、反馈与故障状态；同类型不推定同型号、同协议版本或同额定功率。界面按角色展示：电机供电侧重点为电压与限流，制动加载侧重点为电流；具体设定、输出和反馈能力需手册确认。当前电机电源仍为待接入占位，共用软件模块不改变三路 RS485 各自独立的接线关系。

目标体验：**接好 → 看懂读数 → 开始记录 → 停止并导出**。常用操作留在同一工作界面，串口细节与设备高级参数按需展开。

## 网页交付方案

GitHub Pages 提供静态 HTML/CSS/JavaScript 托管并支持 HTTPS，适合本项目的浏览器界面。CAN 适配器经 Web Serial 接入；传感器可用独立 USB-RS485，两台电源已确定采用网口转 RS485；三路 RS485 分别接线、配置和管理，网关型号、数量、协议与端点配置待定。网络接入根据网关能力使用 HTTP/WebSocket 或本机、台架侧桥接服务，详见[网络接入条件](test-bench.md#网口转-rs485-的网页接入条件)。GitHub Pages 不运行硬件接入后端。[GitHub Pages 说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)、[HTTPS 支持](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https)。

运行链路：GitHub Pages 将网页加载到用户电脑 → 网页通过 Web Serial 访问该电脑的 USB-RS485 → EVG-D200。Modbus 编解码、曲线及记录在浏览器本地完成，方案不上传测量数据。该结构不提供跨互联网远程访问另一台电脑串口的能力。

首版以电脑端 Chrome/Edge 为测试目标，同时用 `navigator.serial` 做能力检测，不只判断浏览器名称。Web Serial 需要安全上下文，首次授权需用户点击触发浏览器端口选择器；`getPorts()` 只能取得已授权端口。[Chrome Web Serial 文档](https://developer.chrome.com/docs/capabilities/serial)、[MDN Web Serial](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API)、[浏览器兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/Serial.json)。

传感器的 USB-RS485 直连路线无需安装专用上位机程序；USB-RS485 仍须被操作系统正确识别，是否需要转接器驱动和串口访问权限取决于实际环境。整套台架是否需要桥接服务，取决于电源网关协议及 CAN 实机兼容性。试验时保持页面开启和电脑唤醒；不承诺关闭页面、电脑休眠后继续采集。高速及长时记录须实测，不从网页方案的可行性推导 1000 Hz 无丢样保证。

发布时仅部署构建后的网页资源，手册、工程笔记和试验记录不作为站点资源自动发布。是否公开源码仓库另行确定。

## 主界面

| 区域       | 内容与行为                                                                                   |
| ---------- | -------------------------------------------------------------------------------------------- |
| 顶部连接区 | 四个设备角色与各自状态；详情中再显示协议、端口、波特率、地址；电机电源当前待接入             |
| 主读数     | 减速箱输出扭矩大数字，始终显示 N·m 和正负号；输出转速及实际制动电流为次要读数；缺失数据用“—” |
| 实时曲线   | 默认扭矩；可切换转速，功率确认量纲后再加入；有时间范围、暂停查看、恢复实时                   |
| 操作区     | 开始/停止记录为主按钮；传感器清零为次按钮；设置独立入口                                      |
| 加载区     | 制动目标电流（A）、输出开关；实际制动电流与减速箱输出扭矩分别显示，电压与电源状态按协议扩展  |
| 电机供电   | 设置抽屉预留供电电压 / 电流读回，当前为“— V / — A”；功能范围确认前不增加控制区               |
| 记录反馈   | 已记录时长、数据量、本地保存状态；结束后提供 CSV 下载                                        |
| 状态反馈   | 区分串口已打开、收到有效数据、正在记录；按需展开诊断信息                                     |

曲线暂停仅冻结视图，不停止采集和记录。实时绘图可降低绘制点数，但记录保留全部有效接收数据；避免绘图阻塞接收。屏幕刷新速度不冒充采样率。

## 连接流程

1. 首次进入显示简短接线提示：独立 24 V 供电、黄线 A、蓝线 B、USB-RS485 端口。
2. 用户点击“连接传感器”，在浏览器授权选择器中选定 USB-RS485；已有授权时可列出已授权端口，记住上次成功配置。
3. 默认尝试 Modbus RTU、19200、地址 1；停止位按手册冲突做有限只读探测。
4. 收到连续有效帧、验证结构和 CRC 后显示“正在接收数据”。若小数缩放尚未确认，要明确显示该状态。
5. 无响应时提供具体下一步：检查供电/端口/A-B/传感器当前模式；高级通信配置再按需展开。

不默认遍历并操作电脑上的所有串口，不把任意串口设备识别成 EVG-D200，不因无响应而写入通信设置。手册没有唯一设备身份寄存器，连接文案不能声称自动认证了硬件型号。

## 首版建议范围

测量模块以单个已选传感器 Modbus RTU 作为联调起点；两种量程配置均需登记，同时运行需求待定。CAN/制动加载模块按试验台方案补充；电机供电模块先确认功能范围，不因新增设备角色而推定控制或联锁行为。若首要场景是毫秒级瞬态，应重新评估高速 HEX 的优先级。

- 连接、断开、保存连接配置及清楚的连接诊断。
- 减速箱输出扭矩/转速读数和实时曲线；功率在量纲验证后加入。
- 传感器清零，清零前说明其会改变设备零点及所有输出。
- 试验记录、停止、CSV 下载和通过文件选择器导入历史记录。
- 断线/数据停更反馈，记录中的缺口与操作事件标记。
- 参数页先显示已读取值；扭矩滤波写入可在读写回验通过后加入。
- 制动电源协议确认后加入电流设定、输出开关及可用反馈；电流上下限与电压上限按实际电源和线圈登记，不由 50/100 N·m 推算。

制动电流输入采用数值框和小步增减，编辑后的值点击“应用”才发送；实际制动电流缺失时显示“—”，电流设定不冒充实测扭矩。输出开关区分请求状态与电源确认状态。连接及重连不自动使能输出或恢复旧设定；“停止记录”“关闭制动电源输出”“停止电机”分开操作。自动恒扭矩控制保留为后续能力。

高级标定、恢复出厂、模拟量校准、自动切换通信模式作为后续范围。两套设备是否同时使用仍待确认；传感器与两电源的 RS485 均使用独立通道。高速模式应有独立引导，说明需要在设备上改回 Modbus，且该模式下远程清零/参数修改尚无已确认通道。

## 清零、滤波与标定

“传感器清零”改变设备零点，不能包装成只改变曲线显示。执行前简短确认当前无扭矩载荷；软件不能凭读数接近零判断是否确实无载荷。执行成功需命令应答及后续读数反馈，记录中写入清零事件；超时不盲目重发状态不明的操作。

“设备滤波”会改变所有输出的动态响应；“曲线平滑”若实现，只影响本地展示。名称、说明及导出字段必须区分，不能静默覆盖原始数据。

“标定”需要已知实际扭矩，调整测量比例；与清零不同。将来可做带原系数备份、输入校验、写入回读的向导，首版无需放在首页。

## 记录与异常行为

建议按试验保存数据及配置快照：开始时间（含时区）、电脑单调时钟相对时间、电脑接收时间、原始整数、换算值和单位、协议、波特率、小数位、滤波及清零/断线事件。加载模块记录制动电流设定、实际制动电流（若支持）、输出开关命令及结果；电机供电读回待协议与功能确认后加入，当前不生成虚构记录。额定量程只在实际规格已确认后保存；未知时保留未知。

记录应增量持久化到浏览器本地存储，结束后提供易读 CSV 下载，避免只把整场试验放在内存里。存储配额、失败恢复和长时记录需验证；不承诺网页可以静默写入任意文件夹。导出失败保留已有记录并允许重试。直接写入用户选定文件可作为后续独立授权能力。数据有效性和导出完整性优先于华丽动画。

| 情况             | 用户看到的反馈                                           |
| ---------------- | -------------------------------------------------------- |
| 串口忙/无权限    | “端口无法打开”，显示原因和可执行的处理步骤               |
| 端口打开但无数据 | “等待传感器数据”，引导检查通信模式及接线                 |
| CRC 或帧结构错误 | 数据质量异常及计数，不把错误帧转成读数                   |
| 断线/超时        | 最后读数标灰，注明最后更新时间；曲线出现缺口，不补零     |
| 重连成功         | 新段继续采集，保留断线事件；不在重连时自动清零或重做标定 |
| 记录/磁盘异常    | 明确显示“记录失败/暂停”及原因，不能继续显示正在正常记录  |

设备没有已确认的采样时间戳或帧序号；导出时间须标注为电脑接收时间，不能宣称精确获得设备采样时刻或物理丢帧率。

## 首版验收重点

- 首次用户能够在不理解寄存器的情况下完成连接与一次记录。
- 读数与实物 OLED、已知输入一致，正负号和小数位正确。
- 拔线后数值明确变旧，记录保留缺口；插回后不静默改配置。
- 曲线暂停不会停止记录，导出的有效数据不因图表降采样而缺失。
- 清零结果可确认，试验记录能追溯清零前后变化。
- 显示实测接收率，区分手册标称上传率和传感器实际更新率。
- 制动电流设定与实测输出扭矩清楚分开；制动电源写入失败、未确认或断线时不显示已执行，重连不自动加载。
- 电机电源待接入时没有伪造的电压/电流反馈，不将供电电流显示为相电流或把减速箱输出扭矩显示为电机轴扭矩。

下一步所需信息：两种规格设备的使用方式；两台同类型电源各自的具体型号、协议版本、额定参数与功能能力，网络网关型号、数量、协议与独立 RS485 通道的端点配置，制动线圈电气参数；传感器 24 V 辅助供电来源；自家驱动板 CAN 协议及固件；实际测试电脑环境与期望时间分辨率。在当前交互原型上逐路实现真实通信并联调，最后部署到 Inntorque/motor-test-bench 的 GitHub Pages。
