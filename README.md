# 电机与减速箱加载试验台网页上位机

仓库：[Inntorque/motor-test-bench](https://github.com/Inntorque/motor-test-bench)（私有）。

目标：让第一次使用的人也能顺利连接试验台、读懂电机与减速箱的输出表现、记录并导出一次加载试验。

设备背景：自家电机、减速箱和 CAN 驱动板，通过扭矩传感器连接磁粉/离合加载装置。用户现有 50 N·m、100 N·m 扭矩传感器各一，以及对应两种扭矩规格的磁粉装置；制动器由电源直接驱动，通过控制电流调节加载。具体配对、是否双台同时使用及电源型号待确认。

当前阶段：已归档并研读手册，完成通信与产品需求初步梳理，并实现 React + Vite 网页交互原型。原型只使用模拟数据，不打开串口、不连接网关、不发送硬件控制命令；真实设备协议与实机联调待完成。

交付方向（2026-10-09 更新）：网页版上位机，目标部署到 GitHub Pages。用户已确认 CAN 适配器为 **LC_CANABLE_V2.1**，可根据方案修改固件；计划采用 USB CDC/SLCAN + Web Serial。首轮 CAN 支持范围固定为经典 CAN 数据帧、11/29 位 ID、0–8 字节，实际速率和电机应用协议随驱动板确认。传感器使用独立 USB-RS485；制动电源按用户提出的网口转 RS485 路线设计，能否由网页直连取决于网关协议，否则增加本机或台架侧桥接服务。当前原型在本地运行，未启用 GitHub Pages。

## 运行网页原型

![模拟试验工作台布局](docs/images/workbench-preview.png)

需要 Node.js 22.12 或更高版本。

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。页面持续显示模拟标识，首屏的“运行加载演示”可以直接体验曲线变化。电机和制动输出默认关闭；电流、转速输入需点击“应用”后生效。

- **试验工作台**：三路设备状态，扭矩 / 输出转速 / 实际电流读数，实时曲线，电机与电流控制，记录与事件。
- **试验记录**：完成的模拟记录保存在当前浏览器，可回看扭矩曲线或导出 CSV。正在记录的数据暂存内存，页面退出前会提示；每场演示最多 1500 点，达到后自动结束记录。正式长时采集的增量存储尚未实现。
- **设备与连接**：抽屉中查看接入计划并模拟断开 / 重连。切换 50/100 N·m 保留连接状态，运行或记录时禁止切换。

CSV 文件名以 `SIMULATION_` 开头，每行 `source=simulation`；扭矩单位 N·m，转速 rpm，电流 A，`receivedAt` 是电脑时间。演示的电流范围、传动比、响应曲线不代表实际设备参数。

## 构建与验证

```sh
npm run build
npm test
```

构建只输出 `web/` 的网页资源至 `dist/`，不包含设备手册、工程文档或试验记录；使用相对资源路径，适合 GitHub Pages 项目子路径。后续发布时选择 `dist/` 为站点产物，保留源码仓库当前私有设置。

浏览器流程验证使用独立临时浏览器配置。先启动开发服务器，再运行：

```sh
npx playwright install chromium
npm run test:ui
```

也可通过 `CHROME_PATH` 指向已有 Chrome 可执行文件，`TEST_URL` 指定测试地址。测试覆盖暂停曲线继续记录、断线缺口、输入应用、量程切换、CSV 导出、记录恢复及四种视口宽度，截图写入被忽略的 `output/`。

源文件：`web/src/App.jsx` 为界面与交互，`web/src/styles.css` 为响应式布局，`web/src/model.js` 为纯模拟模型。真实接入下一步按 CAN、传感器、制动电源三种适配器分离实现，避免将模拟关系用于硬件控制。

初步建议：日常测试先采用出厂 Modbus RTU 模式，把连接、实时曲线和记录导出做好。高速 HEX 上传作为独立能力设计，因为手册说明切入主动上传后不能通过通信切回 Modbus。

待确定：两种规格的使用方式、制动电源和网关型号及协议、线圈允许电流与电压、自家驱动板 CAN 协议、USB-RS485 转接器、实际测试电脑环境和所需数据速度。传感器量程已明确为 50/100 N·m，CAN 板型已明确为 LC_CANABLE_V2.1；转速版本、驱动板协议及固件实机兼容性待核实。
