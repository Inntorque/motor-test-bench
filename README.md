# 电机与减速箱加载试验台网页上位机

仓库：[Inntorque/motor-test-bench](https://github.com/Inntorque/motor-test-bench)（私有）。机械链为 **电机 → 减速箱 → 动态扭矩传感器 → 磁粉制动器**。两台程控电源分别给电机驱动侧和制动线圈供电；电机电源当前使用 SSJ，也可选择万瑞达 RU-36-6060，制动电源保留 SSJ。扭矩传感器测量减速箱输出端，不代表电机轴扭矩。

## 电机电源更新（2026-10-19）

电机电源支持选择 SSJ 或 RU 系列 Modbus RTU，当前使用 SSJ。操作区只保留输出开关，默认固定 **24 V、10 A 限流**；实际直流电流由负载决定，电机 Iq 由电机控制区设置。制动电源默认采用 **恒流 CC 控制**：目标电流仅允许 **0–2.3 A**，电压上限 **24 V**，前后端同时校验；设置目标电流，再开启输出；修改电流后需设置并读回成功，才能开启。连接和页面加载均不写入设定、不打开输出，点击开启才应用并核对设定。原设定值与实际读数分开显示。

选择 RU 时默认 9600、8N1、地址 1，连接自动读取额定 V/A 与小数位。两种协议均由后端校验固定供电参数及额定范围。设备 OVP/OCP 保护只读显示，保留原设置。详见 [RU 电源接入与限幅说明](docs/ru-power-supply.md)。尚未对新电源进行实物通信及输出验收。

## 首页全参数时间序列（2026-10-19）

直接使用原工作台首页的控制与“开始记录 / 停止记录”，无需进入专项测试。完整有效扭矩帧、全部已接入电机反馈、双电源设置/读回/限幅/状态、控制请求与应答按各自时间戳落盘，提供全参数 CSV、完整字段 JSONL 和报告，不受浏览器刷新率及 1500 点限制。记录按钮不改变电机或电源输出；原有控制、曲线和历史保留。详见 [首页完整参数记录](docs/workbench-recordings.md)。已有独立自动脚本仍保留，其说明见 [自动测试文档](docs/automatic-tests.md)。

## 自动专项测试（2026-10-16）

“专项测试”已增加空载和带载顺序脚本：空载定位往返、转速自动搜索与平台观测；带载 Iq 递增、逐帧扭矩记录与本次最大转矩。最高转速、位置/速度偏差和波动如实测量，不预设允许误差或产品合格门槛；控制器限幅、时间预算或保护停止不会被标为电机极限。测试步骤已有可编辑默认值，电流及 NTC 停机保护默认读取设备。使用参考工程已有位置/速度/电流环，沿用编码器换算与 NTC，不改控制参数或保护。点击启动后才运行。详见 [自动测试使用说明](docs/automatic-tests.md)。原有手动控制与 [被动测量](docs/specialized-tests.md) 保留。

台架已确认可连续旋转，自动脚本不设置机械角度上下限。定位按多圈目标点往返，速度与带载测试不因累计转角而停止；保留协议数值范围、电流、NTC、通信及设备保护检查。

## 初始接入记录（2026-10-13）

网页已切换为真实设备状态模式。四个接口初始均显示“未连接”，不生成模拟连接、读数或新试验曲线。电源只有返回有效 Modbus RTU 数据才显示已连接；扭矩传感器需通过只读握手验证通信模式、停止位、小数位及扭矩/转速寄存器后才显示已连接。

两台程控电源使用独立 RTU 通道和状态，复用本地 `SSJ_Control` 已跑通的 Modbus RTU 寄存器方案：读实际 V/A/W 与状态；V/A 同帧写入并读回；开启输出前先写入并核对设定值，之后核对设备输出状态。连接和重连不会自动开输出。断开通讯不改变硬件输出；断线后页面清除读数并将输出状态标为未知。

电源可分别配置串口 RS485，或配置网口 **RTU 透明透传**的网关地址和 TCP 端口。透明透传保留 Modbus RTU 报文；Modbus TCP 转换和网关厂商私有协议尚未实现。电压、电流小数位默认为 2；额定上限需按铭牌填写，不推测设备参数。

EVG-D200 传感器现已接入本机硬件桥，使用独立 USB-RS485 串口与 Modbus RTU，只读采集扭矩和转速，并按 `|扭矩×转速|/9550` 计算轴功率幅值（kW）；原始传感器功率寄存器未因手册量纲不明确而使用。采集数据进入实时读数、曲线、试验记录与 CSV。传感器实物尚未接入，不能视为实机验收完成。CAN 电机驱动板协议仍未接入，完整机械测功控制闭环还需完成 CAN 对接。浏览器里的旧演示记录仍保留，并在历史页标记为历史演示数据。

工作台保留原有量程配置、实时曲线、暂停/恢复视图、试验记录、操作事件、历史详情与 CSV 导出。当前曲线和新记录只由实际设备读回应答驱动；电机控制尚未接入时不会补造控制状态，未连接设备的读数保持空值。

## 启动

Windows / Ubuntu 共用同一套浏览器页面和本机服务。日常使用只运行根目录对应系统的“启动工作台”脚本，或执行 `npm start`，然后在浏览器打开 `http://127.0.0.1:5173/`。入口自动管理网页、双电源/传感器通信桥及电机 CAN 服务，无需分别开终端。

正式运行使用 `dist/` 静态页面，不运行 Vite 开发监听器。Python 网页服务统一转发 `/api` 到本机通信桥；所有服务只监听本机。浏览器不直接占用串口或 CAN，设备操作及完整记录仍在原后端执行。启动服务不会开启设备输出。

首次构建安装 Node.js 22.12+、Python 3.10+：

```sh
npm ci
npm run build
```

Ubuntu 安装本机通信依赖：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-motor.txt
bash 启动工作台-Ubuntu.sh
```

Windows 安装本机通信依赖：

```bat
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-motor.txt
启动工作台-Windows.bat
```

部署时携带构建好的 `dist/`、本工程 Python 文件、`scripts/` 及电机参考工程；两种系统的 `.venv` 和驱动必须分别安装，不能相互复制。有 `dist/` 时，一键脚本日常启动只需要 Python 运行环境；修改网页后重新 `npm run build`。仍可用 `npm run hardware` 和 `npm run dev` 分别启动开发服务。启动入口会复用已运行且身份匹配的本机服务，不强行替换现场服务。

电源面板模式需设为 485 / Modbus RTU，寄存器地址与 `SSJ_Control` 工作版本相同。设定值和额定范围由操作者按具体电源面板及铭牌核对。断开通讯不会关闭电源输出；停止供电需在连接状态下点击 OFF 并确认实际状态。

传感器面板选择独立 USB-RS485 串口，默认 19200 bps、地址 1、8N2；因手册还把默认值写为 8N1，连接前可按传感器参数页改选停止位。桥接程序只读核对 Modbus 模式、停止位、小数位、扭矩与转速，不会远程清零或改写配置。计算轴功率用 `|T×n|/9550` kW，界面及 CSV 均标明为计算量。现场须以 OLED/已知负载核对实际型号、量程与缩放。

## Ubuntu / Windows 一键启动与关闭

工程根目录提供 `启动工作台-Ubuntu.sh`、`关闭工作台-Ubuntu.sh`、`启动工作台-Windows.bat`、`关闭工作台-Windows.bat`。

依赖安装与构建见上面的“启动”。Windows 需要适配器驱动，并在页面选择实际 COM 串口；Ubuntu 需要当前用户具备串口访问权限，页面选择实际 `/dev/ttyUSB*` 或 `/dev/ttyACM*`。串口选择仍在现有界面完成。

电机服务复用已经调通的 `xige_foc` 参考工程，必须保留其中 `scripts/foc_web.py` 及其依赖文件。优先读取环境变量 `MOTORBENCH_XIGE_ROOT`，其次读取工程根目录 `workbench.local.json` 的 `xigeRoot`；未配置时查找相邻的 `xige_foc` / `xige_foc/xige_foc` 及用户桌面同名目录，不再写死用户名和系统路径。

可复制 `workbench.example.json` 为 `workbench.local.json`，配置参考工程路径（相对本工程根目录，或绝对路径）和 CAN 适配器：

```json
{
  "xigeRoot": "../xige_foc",
  "motor": { "interface": "zqwl", "baud": 500000, "node": 0 }
}
```

`channel` 可选：省略时沿用参考工程自动发现；有多个 CAN 适配器时指定，例如 Windows 的 `"channel": "COM4"` 或 Ubuntu 的 `"channel": "/dev/ttyACM0"`。环境变量 `MOTORBENCH_CAN_INTERFACE/CHANNEL/BAUD/NODE` 可覆盖各项。不会猜测两台电源的接线归属。Windows 路径在 JSON 中可用 `C:/设备工程/xige_foc`。若参考工程已有 `.venv`，使用其 Python，否则使用工作台 Python；所用环境须安装 `pyserial` 和 `python-can`。找不到参考工程会明确提示，电源和传感器仍可使用。

启动后打开 `http://127.0.0.1:5173/`。按钮“一键连接全部接口”按页面保存的参数逐个验证两台电源、传感器、电机，不自动开启输出。缺少串口配置、设备无应答等会逐项显示，不猜测串口归属。

日志及本次脚本启动的进程信息保存在 `.runtime/`。关闭脚本终止本脚本启动的进程，以及经目录核对的本工程现有 Ubuntu 开发服务（ai-job-torque-workbench-web/bridge）；其他复用的外部服务保留。电机运行时先请求停止并验证；电源仍输出时提示先在工作台 OFF 后再关闭。断开或退出软件不等于切断硬件供电。关闭前会结束正在进行的首页记录并等待后台文件收尾。Windows 启动使用脱离终端的子进程，关闭启动窗口不会随之关闭服务。Windows 实机串口/CAN 驱动和实际设备仍需在 Windows 上验证。

## 性能优化（2026-10-19）

页面、功能及控制参数保持原样。电源与电机控制面板只在自身数据/输入变化时更新，避免传感器刷新带动所有表单重绘；曲线一次遍历保留相同像素极值与量程结果，历史追加只复制保留范围。有效原始采集帧、后台完整记录、30 次/秒屏幕同步更新、250 ms 电机心跳及 500 ms 制动步进心跳均保持原策略。离线传感器检查间隔降低到 250 ms，健康查询限制单请求在途并设置超时。

电源后台读数与用户操作分开管理：按钮操作显示忙碌并等待已有读取完成，不再因后台读数占用而丢弃点击。电机/制动状态轮询在控制请求期间继续维持心跳，但旧轮询应答不能覆盖控制结果。正式运行使用静态资源缓存，接口继续禁止缓存。

本机 6 万点数据基准：曲线分桶约 2.45 → 1.45 ms，缓存追加约 0.67 → 0.36 ms；该数据仅代表这些计算步骤，不代表整页帧率或整机 CPU 降幅。全页面初始服务端渲染结果与优化前一致。当前现场开发服务保持运行，新启动入口下次启动时使用正式静态网页服务。
